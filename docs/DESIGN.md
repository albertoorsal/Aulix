# 🎨 Design System

## Aulix – Clear. Trustworthy. Efficient.

This document defines the visual design system, UI components and user experience guidelines for the Aulix application.
The goal is a professional, calm and consistent interface for school administrators, teachers and parents, with the same look and feel on every page.

The source of truth for tokens is `applications/frontend-aulix/src/index.css`. Components come from **shadcn/ui** (style `new-york`, Radix primitives) and are styled with **Tailwind CSS 4**.

---

## 1. Design Principles

| 👥 User-Centered | 🧹 Minimal & Clean | 🧩 Consistent | ♿ Accessible | 📱 Responsive |
|---|---|---|---|---|
| Built around real school tasks: find a person, edit, assign, enroll. | Show only what the role needs. Reduce clutter. | One set of tokens and components everywhere. | Keyboard-friendly Radix primitives, visible focus rings, sufficient contrast. | Works on desktop for staff and on mobile for parents. |

## 3. Typography

The primary font is the **system UI stack** (`system-ui, 'Segoe UI', Roboto, sans-serif`): fast, native and highly readable. Code uses `ui-monospace, Consolas, monospace`.

| Element | Size (desktop) | Size (≤1024px) | Weight | Line Height |
|---|---|---|---|---|
| H1 | 56px | 36px | 500 | default, letter-spacing −1.68px |
| H2 | 24px | 20px | 500 | 118% |
| Body (root) | 18px | 16px | 400 | 145% |
| UI text (buttons, inputs, tables) | 14px (`text-sm`) | 14px | 500 / 400 | 20px |
| Caption / Badge | 12px (`text-xs`) | 12px | 500 | 16px |
| Code | 15px | 15px | 400 | 135% |

## 4. UI Components

Standard components used across the application. All live in `src/components/ui/` (generated by the shadcn CLI).

### 4.1 Buttons

| Variant | Use |
|---|---|
| `default` | Primary action on a page or dialog (Save, Create) |
| `secondary` | Secondary actions |
| `outline` | Neutral actions (Cancel, Filter) |
| `ghost` | Icon or row actions in tables |
| `destructive` | Delete, remove, disable |
| `link` | Inline navigation |

Sizes: `xs`, `sm`, `default` (h-9), `lg`, and `icon`, `icon-xs`, `icon-sm`, `icon-lg`. Only one `default` button per view.

### 4.2 Input Fields

- Use `Input`, `Textarea`, `Select`, `DatePicker` with `Label`/`Field`.
- Show validation errors under the field in `text-destructive` (Formik `touched && error`).
- Mark invalid fields with `aria-invalid` so the destructive ring appears.

### 4.3 Cards

- `Card` for grouped content and dashboard tiles: white surface, `rounded-lg`, `border`.

### 4.4 Badges

- `Badge` for status: `SubjectStatusBadge` (ACTIVE → success, INACTIVE → muted), roles, enrollment status.

### 4.5 Alerts & Toasts

- Use **Sonner** (`toast.success`, `toast.error`) for the result of every mutation.
- Error toasts show the backend message (duplicate, not found, service unavailable).

### 4.6 Dialogs

- `Dialog` for create/edit forms (`SubjectFormDialog`, `AddStudent`, `EditTeacher`…).
- Confirmation dialog for every destructive action (`Delete*Dialog`).
- `PersonPickerDialog` for searchable selection of teachers or students.

### 4.7 Navigation

- `AppSidebar` (collapsible to icons) with a **Users** group (Student, Staff, Admin, Teacher, Parent) and top-level entries (Subjects).
- Items are shown only if the user's role allows them (`useHasAnyRole`).
- `Breadcrumb` at the top of each page. `Tabs` for sections of a detail page (e.g., Teachers / Students).

### 4.8 Avatars

- `Avatar` with initials fallback in the header account menu (My Account, logout) and in member lists.

### 4.9 Tables & Lists

- Header row, zebra-free rows with hover, row actions on the right (`ghost` icon buttons).
- Search input + filters above the table, pagination below.
- `Skeleton` rows while loading. An empty state with a short message and a primary action.

## 5. Icons

### 5.1 Icon Library

- **lucide-react** only. Default size `size-4` in buttons and menus.

### 5.2 Usage Guidelines

| Concept | Icon |
|---|---|
| Brand / Students | `GraduationCap` |
| Users group | `Users` |
| Subjects | `BookOpen` |
| Expand / navigate | `ChevronRight` |

Icons support text, they never replace it. Icon-only buttons need a `tooltip` or `aria-label`.

## 6. Layout & Spacing

### 6.1 Spacing Scale

Tailwind's 4px scale: `1`=4px, `2`=8px, `3`=12px, `4`=16px, `6`=24px, `8`=32px. Use `gap-*` for layout spacing, not margins.

### 6.2 Radius

`--radius: 0.625rem` (10px). `rounded-sm` = radius − 4px, `rounded-md` = radius − 2px, `rounded-lg` = radius.

### 6.3 Container Widths

- `DashboardLayout`: `SidebarProvider` + `AppSidebar` + `SidebarInset`, with a 64px header (`h-16`, `border-b`, `px-4`) above the page content.
- Forms in dialogs: max width `sm:max-w-lg`.

## 7. Responsive Design

### 7.1 Breakpoints

Tailwind defaults: `sm` 640px, `md` 768px, `lg` 1024px, `xl` 1280px. Root font size drops from 18px to 16px at ≤1024px.

### 7.2 Mobile First

- Write base styles for mobile and add `md:`/`lg:` overrides.
- The sidebar becomes a `Sheet` on mobile (`use-mobile` hook).
- Tables scroll horizontally inside their container on small screens. The page never scrolls sideways.

## 8. Page Templates

### 8.1 Auth Pages

- Centered card on `bg-background`, brand mark, email + password, primary "Sign in" button, inline errors.

### 8.2 Dashboard Layout

- `AppSidebar` on the left. The header has the sidebar trigger and breadcrumb on the left, and the account menu (avatar) on the right. The notification bell is added in Phase 11. Content goes below.

### 8.3 List Pages (Students, Staff, Teachers, Subjects, Users, Parents)

- Title + primary "Add" button → search/filters → table → pagination.

### 8.4 Detail Pages (SubjectDetail, User detail, Parent detail)

- Header with name, status badge and actions → `Tabs` for related data → member lists with assign/remove actions.

## 9. Illustrations & Graphics

### 9.1 Style

- Minimal. Use lucide icons inside a tinted circle for empty states. No stock photography.

### 9.2 Usage

- Empty states, 404 / fallback screens and the login page only.

## 10. Animation & Interactions

### 10.1 Transitions

- `transition-all` / `duration-200` for hover and color changes. Collapsibles use `animate-collapsible-up/down` (tw-animate-css).

### 10.2 Hover States

- Buttons darken (`/90`, `/80`). Rows and ghost buttons use `hover:bg-accent`.

### 10.3 Loading States

- `Skeleton` for lists, a disabled button with a spinner for submits, and a full-screen "Loading…" only during the initial `checkAuth`.

## 11. Dark Mode

### 11.1 Theme Colors

- Defined under `.dark` in `index.css` (see §2).

### 11.2 Implementation

- `@custom-variant dark (&:is(.dark *))`: any element under `.dark` uses the dark tokens, and components switch automatically.
- `next-themes` is installed (used by the Sonner toaster), but there is **no theme toggle in the UI yet**. Adding one (`ThemeProvider` with `attribute="class"` and a toggle in the account menu) is a future enhancement.

## 12. Accessibility

- Contrast ≥ 4.5:1 for text.
- Every input has a `Label`.
- Visible focus ring (`ring-[3px] ring-ring/50`).
- Dialogs trap focus and close with `Esc`.
- Color is never the only signal: status badges include text.
